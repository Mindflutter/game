**Goal:** a dive that runs on through two layers, and the loop around it —
gems banked, a gun bought, a point earned and spent, the whole thing saved.

**Spec:** `docs/superpowers/specs/2026-09-30-s4-meta-loop-design.md` (approved
in chat in three parts). Every number marked there as Claude's pick goes into
the `// balance` block marked as such.

**Architecture:** content first — `LAYERS` (stretches of pools), `FILLERS`,
`GEAR`, `ATTRIBUTES`, `TASKS` and the `home` menu are records in
`game/content.js`. `reset()` draws the dive's whole `plan` from the seed and
builds the player from `PLAYER_START` + gear + attributes. The persistent
record is one `meta` object in `game/state.js`; `saveText()` / `loadSave()` /
`snapshot()` / `restore()` live in `game/`, and `persist(text)` is the one new
seam name. `main.js` loads at boot, writes on `pagehide`/hidden, and makes
`persist` a no-op under `?test` and `?dev=` so no check ever touches a real save.

**Tech:** plain JS, Canvas 2D, Vitest + fast-check (dev only).

## Review focus

1. A check run (`?test`, `?dev=`, Node) must never overwrite the player's save.
2. A save that does not parse, or has an unknown version, must not be
   overwritten by the next write — copied aside first, and said on screen.
3. Restoring a dive restores *every* variable: a forgotten one diverges the
   D70 property check — that check is the guard, so it must compare the whole
   snapshot, not a summary.
4. A gems card must not pay when merely *previewed* on a card.
5. Death on the frame of a layer-end kill: death outranks the milestone, as it
   already outranks a rank-up.

## Tasks

Each ends with `npm test` green; each behavioural change lands with a check
verified by breaking the rule it guards.

1. **Layers and the plan (D71, D66, D72).** `LAYERS` replaces `BATCHES`: two
   layers sharing one set of stretches, one new batch per ordinary stretch.
   `drawPlan()` at reset; the queue spawns `plan[batchIndex].batch`; the bottom
   is `plan.length`. Screen `'bottom'` → `'won'`. Scenarios' `batch` may be a
   function of the plan. Render: water colour and the layer name derived from
   the plan and the camera — no new state. Tests: D71 (same seed same plan, two
   seeds differ, pool membership, no repeats), layer shape (boss last in each
   layer, two mini-bosses each), carrying on through the layer end.
2. **The milestone and the caps (D68, D69).** Layer end: full heal, rank,
   cards; last layer's end none, then the win. Boss `value` 30. Fins and
   Vitality `max: 3`. `FILLERS` (gems 10, a heart) fill the offer; not
   previewed, not counted. The empty-offer branch goes. Tests for each.
3. **Gems collect themselves (D35, D67).** Every gem pulls to the player;
   `GEM_LIFE`, expiry and `pickupRange` go. Test: every dropped gem is
   collected wherever the player stands.
4. **The kit scenario.** `layer-2` starts at layer 2's first gate with a stated
   kit, applied as picks. Test: it loads there with the kit held.
5. **Meta: gear, attribute, micro-task, banking.** `meta` = `{ version, bank,
   gear, spent, tasks, deepest, cleared }`. `buy()` / `raise()`; `points()`
   derived. `reset()` applies tiers and points. `batchHit` per batch;
   `TASKS` judged at each clear, once per layer. `endDive()` at death and win
   banks the dive's gems, deepest, cleared. Tests: the sums, affordability,
   top tier, once-per-layer, not after a hit, banked on death.
6. **The save (D70).** `snapshot()` / `restore()` / `saveText()` /
   `loadSave(text)` returning an error or null; `SAVE_VERSION = 1`.
   `persist` written on pause, at dive end, on purchase. Seam: seven. Fixture
   `tests/fixtures/save-v1.json`. Tests: the property (save at a random tick,
   restore, both play on, whole snapshots equal), round trip of meta, bad JSON
   and unknown version rejected, fixture loads.
7. **`home` and the screens.** Title Start → `home` / Continue → paused dive.
   `MENUS.home` with getter labels and a `top`; drawn by `drawMenu` plus the
   layer list. Death and win lead home; R dives again. The rejected-save line
   on the title. `?test` checks updated; a layout check for `home`.
8. **Measure** with the bot: gems per dive, dives to first purchase, tier 0 vs
   tier 1 on the same seeds, layer 2 from its scenario → `roadmap.md` → Health.
9. **Look at it**: screenshots of `home`, a layer crossing, the win screen;
   `?test` run in the browser.
10. **Sweep**: checks, `docs/` (changelog, decisions D74+, design, plan,
    ideas, roadmap), `foundations.md` (seam count), `CLAUDE.md` (seam count),
    in-game text (proposed wording flagged to Igor), layout, memory. Raise the
